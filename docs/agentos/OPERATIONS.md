# Guarded launch operations

Installation follows docs/INSTALL_UPDATE.md: verify exact source/wheel hashes and disjoint core/user roots, plan the managed installer, then apply only against the observed current release. The installer is offline and preserves predecessor releases and user data. An advisory update is not install authority.

Verification requires installed payload/version/resources and current pointer readback, managed integration preimages and a fresh supported-client entry. A listed process or wheel string is not behavior proof. Test genuine persistence/continuation and existing workers separately.

Update only reviewed artifacts and managed AGENTS/skills; personal overlay reconciliation has its own exact preimages and hashes. Do not replace auth/config/model/approval/sandbox settings or unrelated services.

Rollback is planned and rehearsed in an isolated contour, using the verified predecessor/current identity. Preserve target authority and reconcile uncertain writers before retry; rollback does not cancel prior effects. Never restore hooks or a retired kernel.

Recovery retains failure evidence and inactive incomplete releases. Inspect exact locks/processes; do not clear a gate by age, reset unknown effects, or manufacture acceptance.
