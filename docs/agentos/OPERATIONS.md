# AgentOS engineering operations

## Installation
Use the existing offline managed installer after source, wheel, environment and free-space checks. Review the plan and apply against the exact observed current release. The selected user overlay stays separate and unchanged. Installation of the CLI does not restart business services or prove adoption by existing chats.

## Verification
Verify exact package bytes and declared contracts, source/build provenance, entrypoints, module pins and a fresh harmless diagnostic call. Inspect real project readbacks with private records stored in their owning roots. Preserve all failing evidence alongside later success.

## Update
Integrate only reviewed changes. Generate mirrors through existing sync tools, validate the build from the final source, independently review and publish through the canonical branch/PR route. Never use a version string alone to replace an installed feature set.

## Rollback
Retain the exact compatible predecessor and rehearse pointer rollback in isolation. Reject proven reader loss or conflicting explicit declarations; report undeclared legacy compatibility as UNKNOWN without inventing a new hold; do not reset or discard pending project journals. Keep one justified rollback per deployment family and follow the host's existing retention contract.

## Recovery
Use exact original operation identities and readback for unknown outcomes. Preserve locks and foreign writers; do not clear them by age. A blocked effect does not prevent independent source preparation. Record actual result, remaining criterion and next responsible action at each checkpoint.

## Low-friction default
Known adjacent build receipts are selected automatically when they match the wheel. The normal install flow gains no new required flags. Read-only diagnosis is optional; it offers one affected next action and never initializes a second project center. Relevant source checks belong to the change being made, not to every read or conversation.
