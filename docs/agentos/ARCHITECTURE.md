# Guarded session architecture

The public foundation remains host-neutral and separate from the private user overlay. Current source is the 0.7.1 candidate built on the canonical 0.7.0 baseline, including the reviewed guarded-launch correction. Publication and live adoption require separate verification.

Provider-neutral session admission validates an explicit request, original goal, known answers, current authority, required capabilities and target gates. A Codex adapter reads inherited configuration and the complete bounded model catalog on one App Server stdio connection before thread creation. Actual startup readback and harmless tool evidence precede original work. GNU Screen owns a persistent worker and the same connection/thread; it does not detach after an immediate business command.

Context materialization returns bounded selected document bodies with exact hashes and caller binding. Construction is not proof of cognition or compliance. Existing legacy TUI Screen sessions are a separate compatibility path. Preserve current writers and reconcile uncertain effects before replacement.

Sources: public src/agent_os/session_hub.py, session_launch.py, codex_launch.py, screen_launch.py and context_gate.py; docs/ARCHITECTURE.md and docs/WORK_COORDINATION.md. Live acceptance is separate.
