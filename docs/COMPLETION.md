# Versioned completion API contract

Schema: `agentos.completion/v1`, optional embedded extension of the existing Coordinator snapshot. Unactivated HEAD remains `agentos.work-coordination/v1`; explicit completion activation promotes the same existing backend to `agentos.work-coordination/v2`, which old 0.7.1 readers reject before writing. Activation requires backup and unsupported downgrade uses verified predecessor restore. This contract supplements the unchanged supplied TZ; it defines the minimal implementation API selected at P1.

`activate_completion(actor, expected_revision, contract, policy, checked_at, dry_run=False)` validates original goal/criteria, task identity, immutable source/build/contract/config/environment dependencies, acceptance reviewer, registered criterion recipes, budget and deterministic bounds. Activation is explicit; existing legacy snapshots do not change on read. It rejects any legacy in-flight/planned command before activation. Before promoting HEAD it stores and rereads the exact predecessor snapshot, retaining `activation_backup_ref`; failed backup verification leaves the old HEAD untouched. This state backup does not replace a reinitialization's tracked/untracked/source checkpoint. Dry-run writes nothing. Defaults: maximum 3 attempts per idempotent operation, 2 strategies without semantic progress, 1 admitted command, 5/20/60 seconds backoff with bounded deterministic jitter; lease 60 seconds, refresh 20 seconds, capability TTL at most 300 seconds, ACK timeout 120 seconds. Values are explicit test/development configuration, not promised service SLAs.

`completion_event(actor, expected_revision, event, checked_at)` consumes bounded event identities atomically with project state evaluation. Fields: event_id, kind, generation, causal_sequence, observed_at and payload. Old generation/sequence events are retained as audit-only. Cancellation is terminal and dominates replay. Events never accept an outcome by themselves. A repeated identity must have the same canonical event bytes; a conflicting replay is rejected. State, event and any proposed outbox command share the atomic snapshot commit.

States: DRAFT, READY, RUNNING, VERIFYING, WAITING_USER, WAITING_EXECUTOR, BLOCKED_POLICY, BLOCKED_BUDGET, BLOCKED_NO_PROGRESS, BLOCKED_UNKNOWN_OUTCOME, BLOCKED_UNSAFE_TAKEOVER, ACCEPTED, CANCELLED, FAILED_FINAL. Parent completion is a projection of ACCEPTED only. Turn, child and delivery statuses remain separate. `completion_status(checked_at)` gives actual observed source/freshness, next action owner and explicit gaps. Requested/assigned model do not populate actual model.

`completion_plan(actor, expected_revision, checked_at)` creates at most one operation from an unmet criterion's registered recipe. It requires the exact canonical operation capability, adapter/runtime version and evidence, target class/scope, current TTL, current policy and budget. Aliases message_send→send and task_create→start normalize explicitly. No alias fallback, read/send equivalence or new-session substitution exists. WAITING states, pending reconciliation and exhausted semantic-progress bounds never issue another model turn.

`completion_begin_dispatch(actor, expected_revision, operation_id, checked_at)` durably marks unknown outcome before I/O and returns one immutable attempt identity: task/generation/ownership epoch/cancel fence, operation/idempotency key, target/receiver/data/environment, source dependencies, policy revision, attempt nonce and strategy. Repeating an UNKNOWN dispatch is refused, regardless of lease timeout.

`completion_receiver_admit(actor, expected_revision, identity, checked_at)` is the supported local gateway's atomic effect boundary. Recheck exact current capability/policy/lease/generation/epoch/cancel fence and admission identity, then durably deduplicate the command. Only NEW_ADMISSION authorizes a new effect. Execution occurs outside the store transaction. A duplicate admitted command returns ALREADY_ADMITTED and must be reconciled, not executed again. Admission does not undo an already admitted effect if cancellation subsequently arrives; it retains that outcome debt and blocks new effects.

`completion_record_result(...)` requires the admitted operation identity and captured durable execution receipt from the selected adapter. PASS requires actual existing evidence bytes, zero exit code, actual recipe/runtime/workspace and all current dependency hashes. A successful turn is not criterion semantic acceptance. The evaluator uses source-bound evidence and invalidates the affected acceptance after dependency changes.

`completion_reconcile(...)` invokes the selected exact-operation verifier outside the transaction, then atomically records only bound authoritative provider evidence. Empty eventual queries, offline errors and unclassified responses retain UNKNOWN. Confirmed non-admission permits a bounded same-identity retry only before a verified deduplication/processing horizon. Completed/running/admitted evidence does not permit replay. Known terminal delivery evidence remains audit after source change/cancellation without accepting the new generation.

`completion_review(...)` records an independent named review bound to current source/contract/config/environment, all current criterion receipts, captured artifacts and findings. The configured reviewer must differ from the implementation actor. A missing receipt, changed dependency, blocking finding or unverified bytes prevents acceptance. `completion_prepare_handoff(...)` binds safe exact relative inventory, source commit, contract/manifest hashes, scope, receiver, expiry, ownership transition and next step. Receiver verification independently checks transferred bytes, checkout and dependencies. `completion_ack(...)` checks the actual bound receiver evidence; sender enqueue never supplies it. REJECTED or stale/late ACK cannot change ownership or accept the task. Switching owner needs fresh verified ACK, a new fence and safe takeover.

`completion_takeover(...)` needs effect fencing at the actual receiver, or independently verified old-writer quiescence plus all in-flight reconciliation. A timeout/PID/owner label is insufficient. An old paused sender is denied at receiver admission. Any unresolved old effect remains blocked even after a new owner takes over.

`completion_checkpoint(...)` pauses only the selected coordinator dispatch and captures verified snapshot plus explicitly selected workspace tracked/dirty/untracked bytes, budgets/policy/ownership/ledger/inbox/outbox and process inventory. The supported local canary proves actual process identity and child termination; no unknown existing worker is probed or killed. Rehearsal restore verifies artifacts and invariants. `completion_restore(...)` requires exact checkpoint, current target authorization, quiescence/fencing and reconciliation; it increments generation/epoch/cancel fence, preserves terminal cancellation and never renews expired policy. Unsupported downgrade is rejected before any write; predecessor recovery uses the verified backup after safe quiescence.

Goals operations stay opt-in. Unsupported/denied/detected-but-unverified Goal state never enables continuation or weakens core safety. A Goal budget event records a blocker; a Goal completion event still requires product acceptance. This local adapter does not claim a qualified Codex Goals integration.

Authentication and live policy source verification belong to the selecting adapter; hashes and actor strings cannot authenticate a principal. Explicit gates do not supply an OS sandbox. Only the isolated local registered-command runner is qualified by this change. Remote/cloud adapters must prove their own current identity, capabilities, receiver fencing and actual effect receipt before enabling completion dispatch.

Admission also requires capability_snapshot_hash, capability_checked_at, capability_expires_at, policy_scope_hash, policy_expires_at and checked_at. The versioned strict freshness validator requires 0 <= capability_checked_at <= checked_at < capability_expires_at, capability TTL <= 300 seconds, and checked_at < policy_expires_at. It compares expected capability/scope hashes to freshly resolved current snapshot bytes; mismatch rejects admission. JSON Schema validates shape; these relational checks are independently tested, never inferred from schema-only PASS. Event payload has a closed per-kind discriminator in the versioned schema; a TURN_FINISHED payload identifies the actual turn/executor/status, and effect-bearing notices identify their exact operation/receipt. Events are notices rather than authority grants. The input assignment ACK is distinct from later artifact/ownership ACK.


## Bounded invocation and reporting
`LocalCompletionRunner.run_bounded(coordinator, actor, clock=current_clock, max_steps=3)` invokes at most the explicit number of registered steps. The selecting adapter supplies authenticated current authority/dependency readers and a current authoritative clock; the runner rereads that clock at every effect boundary. WAITING_USER, stale lease, unknown outcome, paused transfer, terminal status or a budget/strategy stop returns immediately without sleeping, polling or model turns. It has no automatic Goals enable operation. This adapter runs only start/resume argv recipes; it cannot masquerade as send, native Handoff, artifact transfer or Goals.

`completion_route_error(...)` records one exact target/environment/operation error. Independent read capability survives a failed write/resume route. A denied scope cannot be expanded by an alias or another adapter. Registered alternatives are limited to one preapproved strategy under the same criterion and exact current policy; original failed receipts remain in evidence.

`completion_public_status(checked_at)` provides source, observed age/freshness, remaining count, precise blocker and the next permitted action without private IDs or an invented percentage. Internal status retains actual ownership and receipt identity for authenticated operators. Actual model stays UNKNOWN without qualified telemetry; the local argv runner does not infer an LLM model from an assignment.

TRANSFER_OWNER ACK verification commits a paused source with ACK_VERIFIED_PENDING_TRANSFER and NOT_DELIVERED. No source work can be dispatched in that interval. A fresh target policy/fence proof then commits ACKED plus the new owner/epoch together. There is no accepted transfer while the old owner can dispatch. Byte-identical ACK replay is a read. Old-epoch/cancel-fence results are audit-only; authoritative non-admission may rebind a same-key retry to the current epoch. Event IDs retain their hash index after batch archival; replay conflict remains rejected.

Execution receipt ingestion requires an authenticated exact-execution verifier as well as actual stored bytes. A source-only assertion, actor label or archived log cannot establish host acceptance. Reconciliation likewise requires actual independently retrieved byte evidence, exact nonce/epoch and a causal timestamp; empty eventual reads never authorize retry.

`evaluate_completion_release` extends the existing result gate. It reads current candidate bytes and dependency-bound G0–G4/T22/T27/T32 receipts, then separately checks exact current publication authority. PREPUBLISH can return READY_TO_PUBLISH only; POSTPUBLISH requires independently retrieved actual published bytes and install evidence. It performs no external effect. A synthetic evaluator PASS grants no real authority.

A restored generation never authorizes replay of a completed or authoritatively reconciled identical prior effect. If its old result cannot establish current semantic acceptance, planning requires an explicitly preapproved alternative verification recipe or a newly authorized changed exact scope; incrementing generation alone is insufficient.

Declared release scope: [support matrix](completion/SUPPORT_MATRIX.json). Actual qualification belongs to separate candidate-bound receipts.
