# Public foundation and external execution

## What the public foundation requires

Use the public package, its applicable project documentation and local checks
for project governance. No private AgentOS installation, release-candidate pin,
fleet controller, signer, host profile, message bot or notification service is
required for that workflow. The core provides no production deployment loader.
A user overlay stores selected knowledge and configuration; it does not make a
private executor mandatory or grant host authority.

For a new application, use that application's source, build, runtime and
installation contract. Reusing an existing service is optional and must be
explicitly justified by the application or target contract. Do not make a private
foundation upgrade a launch prerequisite merely because the host has it installed.

## Choose the current target contract

Before an external effect, identify the exact target, actor, operation and
owner-authorized scope. Read only the target's relevant current instructions.
Classify a proposed gate before treating it as mandatory:

| Evidence | Meaning and action |
| --- | --- |
| Old task report, RC pin, remembered controller or inherited generic skill | Historical or advisory information; verify current applicability before using it |
| Current scoped host rule or an executor that enforces the operation | Applies to that target effect; preserve it and identify the exact policy/permission needed |
| Missing profile in one optional provider | That provider lacks the operation; it does not prove every permitted executor lacks it |
| Existing independently permitted execution path | Verify its actor, scope, target, preimages, concurrency protection and rollback before use |
| Enforced refusal from the selected target path | Stop that effect; never switch path to evade the refusal or disable the control |

Root SSH proves an operating-system identity; it does not settle applicable
policy. Conversely, an unsigned application artifact or a private controller's
missing profile is not by itself proof that a private loader governs all shell
operations. Attribute the actual restriction to its current source. If evidence
is incomplete, state what has and has not been established.

## Keep blockers specific

Continue authorized documentation, implementation, packaging and checks while
one target effect is blocked. Report:

1. The exact operation that remains unavailable.
2. Whether this is a current target policy, technical denial, missing credential,
   missing provider capability, or unverified inherited instruction.
3. The evidence and the authorized party or mechanism that can resolve it.
4. The minimum next action and the work that is already complete.

A target-policy migration requires separate explicit scope and a reviewed plan.
Do not edit a loader, ACL, signer inventory, service, or deployment policy simply
to make the application launch. An owner's approved migration may remove a
legacy dependency after verification; public project READY does not perform it.
Do not require reconstruction of a former private platform as the default fix.

## Optional reporting

Send a notification only when the owner has authorized that destination and
purpose, or an applicable current user policy explicitly authorizes it. Select
the current provider and verify identity, recipient, rendering and receipt.
Absent, failed or uncertain reporting does not invalidate completed local work
or prevent an in-chat result and a saved report. Do not fall back to raw sends,
change recipient/provider to evade refusal, or claim delivery without a receipt.
Inbound reply routing is a separate capability.

## Where the knowledge belongs

Public core owns this selection and diagnosis method. A user's provider choice
and integration settings belong in the external overlay. Exact deployment and
runtime procedures belong with the target project or service. Dated RC/fleet
reports remain historical evidence. A local skill must declare its target
applicability and cannot silently turn a provider-specific procedure into a
universal AgentOS rule.

This guide changes documentation, not target enforcement. Shipping it does not
prove an existing host has migrated its private runtime or admitted a new
application operation.
